# Galaxy Z Fold8 실기기 시험계획

## 시험 대상

v1.4.0은 설정값 `screen_auto_brightness_adj`를 쓰지 않습니다. 조도 센서값으로 삼성 자동 밝기 목표를 조회하고, 보정한 결과를 임시 패널 밝기로 적용하는 포그라운드 서비스를 시험합니다. UI 시험에서는 7단계 프리셋, 슬라이더 끝단, 선택 상태, 숫자·손잡이 후광과 주요 버튼의 잘림·겹침도 함께 확인합니다.

## 준비와 기준 상태

1. Fold8에서 자동 밝기를 켭니다.
2. 공식 Shizuku를 시작하고 앱 권한을 허용합니다.
3. USB 디버깅 연결을 확인합니다.

```powershell
adb devices -l
adb shell settings get system screen_brightness_mode
adb shell settings get system screen_auto_brightness_adj
adb shell cmd display get-brightness
```

기준: `screen_brightness_mode=1`. 시험 전 `screen_auto_brightness_adj` 값을 기록하고 시험 중 변경되지 않는지 확인합니다.

## 기능시험

### T1. Shizuku 흐름 — PASS

- 미설치, 미실행, 권한 필요, 연결 중, 준비 완료 상태를 문구로 구분합니다.
- Fold8에서 공식 Shizuku 실행과 앱 권한 허용 후 UserService 연결을 확인했습니다.

### T2. 실제 밝기 적용 — PASS, 펼친 화면

같은 조도 약 `135 lux`에서 확인한 결과:

| 보정 | 삼성 기본값 | `mScreenBrightness` |
|---|---:|---:|
| `+20` | 약 `0.3216` | `0.40222412` |
| `-20` | 약 `0.3216` | `0.24332996` |

앱 화면의 `+20` 선택과 적용 버튼으로도 같은 서비스 적용을 확인했습니다.

확장된 끝값은 약 `186~187 lux`에서 다음과 같이 확인했습니다.

| 보정 | 삼성 기본값 | `mScreenBrightness` |
|---|---:|---:|
| `+100` | `0.3372549` | `0.6960698` |
| `-100` | `0.3372549` | `0.038359668` |
| 시험 전 사용자값 `+50` 복원 | `0.3372549` | `0.5339082` |

v1.4.0 커버 화면 추가 시험:

| 보정 | 삼성 기본값 | `mScreenBrightness` |
|---|---:|---:|
| `0` | 시스템 자동값 | `0.33397412` |
| `+75` | `0.32941177` | `0.6143789` |
| 사용자값 `+50` 복귀 | `0.32941177` | `0.5267039` |

### T3. 조도 추적 — PASS, 제한된 실내 범위

- 서비스가 `136 lux`에서 기본값 `0.3216`, 보정값 `0.4022`를 적용했습니다.
- 센서값이 기존 허용 범위 아래인 `42 lux`로 바뀌자 기본값 `0.2745`, 보정값 `0.3542`로 다시 계산했습니다.
- 어두운 방, 창가, 야외 고휘도는 추가 체감시험이 필요합니다.

### T4. 화면 OFF/ON — PASS

1. 보정을 적용합니다.
2. 화면을 끕니다.
3. `mTemporaryScreenBrightness:NaN`인지 확인합니다.
4. 화면을 켭니다.
5. 새 lux를 읽고 보정값이 다시 적용되는지 확인합니다.

Fold8에서 화면 OFF 시 해제, 화면 ON 시 `136 lux` 재측정과 `0.4022` 재적용을 확인했습니다.

### T5. 복원 — PASS

앱의 `원래 값 복원`을 누른 뒤 다음을 확인했습니다.

- 관리 서비스: STOPPED
- `mTemporaryScreenBrightness:NaN`
- `mTemporaryAutoBrightnessAdjustment=NaN`
- `screen_brightness_mode=1`
- `screen_auto_brightness_adj=0.00`
- 실제 밝기: 시스템 자동값 약 `0.3229`

### T6. 커버 화면 — PASS / 커버·메인 연속 전환 — 현장 검증 필요

v1.4.0을 활성 커버 화면 `1248 x 1972`, `420 dpi`에서 확인했습니다. 7개 프리셋, 숫자·손잡이 후광, 끊김 없는 막대, 적용 버튼, 하단 토글·복원·진단 영역이 잘림 없이 표시됐고 `0 → +75 → +50` 실제 적용도 PASS했습니다.

`+10` 적용 상태에서 접기 → 커버 확인 → 펼치기 → 메인 확인 → 다시 접기를 반복합니다. 각 상태에서 활성 물리 화면과 논리 display ID, 임시 밝기, 센서 재계산을 기록합니다.

합격 기준: 두 패널 모두 자동 밝기와 보정 효과가 유지되고, 꺼진 패널에는 고정 오버라이드가 남지 않습니다.

### T7. 앱 강제 종료·업데이트 — PASS / Shizuku 자체 중지 — 현장 검증 필요

- `adb force-stop`: Shizuku UserService 종료 훅이 임시값을 `NaN`으로 복원하고 시스템 자동값 약 `0.3229`로 복귀 — PASS
- 앱 재실행: 저장된 `+20` 관리 서비스와 임시 밝기 자동 재개 — PASS
- 동일 APK `install -r`: 저장된 `+10` 관리 서비스와 임시 밝기 자동 재개 — PASS
- Shizuku 앱 자체 중지: 추가 현장 검증 필요

### T8. 재부팅 — PASS, Shizuku 수동 재시작 필요

비루트 Shizuku는 재부팅 후 다시 시작해야 합니다. Fold8 재부팅 후 Shizuku를 수동으로 시작하고 앱을 열자 마지막 관리값이 재적용됐습니다. ADB로 Shizuku 서버, 밝기 관리 서비스, 실제 임시 패널 밝기를 확인했습니다.

### T9. 언어·알림 — 현장 검증 필요

- 한국어 시스템: 한국어 UI와 알림
- 영어 및 기타 시스템 언어: 영어 UI와 알림
- Android 알림 권한 허용·거부 상태
- 알림의 `보정 해제`로 서비스 종료와 원상복구

## 자동 검증

Debug 빌드에는 `android.permission.DUMP`를 요구하는 ADB 전용 시험 Receiver가 있습니다. 일반 앱은 호출할 수 없고 Release 빌드에는 포함되지 않습니다. 조도 샘플, 삼성 곡선 조회, 임시 밝기 적용, Repository 적용·복원을 반복 검증하는 데 사용합니다.

PC 검증:

```powershell
.\scripts\verify.ps1 -IncludeRelease
```

실행하지 않은 실제 패널·재부팅·언어 시험은 PASS로 기록하지 않습니다.
